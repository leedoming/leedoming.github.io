담당 업무 ↔ 검증된 경험

교보문고 IT클라우드팀 공고의 5개 담당 업무를 실제 운영·프로젝트 경험으로 매핑했습니다.

저는 클라우드/컨테이너 기술을 "구축 대상"이 아니라, 개발 조직이 안정적으로 배포하고 사용자가 끊김 없이 서비스를 이용하게 만드는 운영 기반으로 이해합니다. 아래는 공고의 담당 업무별로 제가 실제 무엇을 해봤는지 정직하게 정리한 표입니다.

01

CI/CD 파이프라인 운영 지원

Jenkins·ArgoCD 기반 빌드·배포 흐름 / Canary·Blue-Green 무중단 배포

졸업 프로젝트에서 GitHub Actions로 PR이 merge되면 EC2 서버에 자동 반영되는 배포 파이프라인을 직접 구축했고, X-ray 탐지 프로젝트에서는 AWS CodePipeline(Build→Deploy)과 Stage→승인→Prod 배포 게이트를 설계·운영했습니다. Jenkins·ArgoCD·Canary·Blue-Green은 동일 계열의 CI/CD 개념 위에서 구조를 이해하며 학습 중이라, 실무 도구 전환에 빠르게 적응할 수 있습니다.

04

교보문고 도메인 이해

인프라 역량이 메인이고, 도서·콘텐츠 도메인 이해는 이를 뒷받침하는 강점입니다.

도서·콘텐츠가 어떻게 서비스가 되는지 이해합니다

문헌정보학을 복수전공하며 자료 분류·메타데이터·정보 구조화 관점을 익혔고, 전공 프로젝트에서 직접 도서를 기획·편집해 인쇄물로 완성하며 책 한 권이 독자에게 전달 가능한 형태가 되기까지의 제작 과정을 경험했습니다. 인스타페이에서는 어린이가 카드형 선택지로 스토리를 구성하면 AI가 그림·TTS를 생성해 EPUB 전자책으로 변환하는 어린이 도서 제작 플랫폼 기획을 담당하며, 종이책과 디지털 전자책 양쪽에서 도서 콘텐츠가 만들어지고 서비스화되는 흐름을 이해했습니다. 덕분에 교보문고의 전자책·온라인 주문·매장 재고 확인·바로드림 같은 서비스가 데이터로 어떻게 구성되고 운영되는지를 이해한 상태에서, 이를 뒷받침하는 인프라에 접근할 수 있습니다.

도서·콘텐츠 데이터  →  검색·전자책 서비스  →  무중단 배포·안정 운영  →  끊김 없는 독자 경험

왜 이 이해가 인프라 직무에 도움이 될까

인프라·클라우드 엔지니어라도 결국 회사의 서비스를 뒷받침합니다. 도서 검색·추천·전자책 플랫폼이 어떤 데이터와 흐름으로 동작하는지 아는 사람은, 장애가 사용자에게 어떤 영향을 주는지, 어떤 배포가 서비스에 안전한지를 더 빠르게 판단합니다. 저는 기술 스택은 클라우드/컨테이너로, 태도는 운영으로, 결과는 비용·속도·안정성으로 정렬해 교보문고 서비스의 안정성에 기여하고 싶습니다.
